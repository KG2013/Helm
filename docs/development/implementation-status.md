# 当前实现状态

核对日期：2026-10-04。本文以本仓库代码和 2026-10-03 验收记录为依据；[架构基线](../design/architecture-v0.md) 和 accepted ADR 表达目标，实时供应商/Office 依赖仍按环境边界单独标注。

## 已建立的骨架

| 模块 | 当前代码行为 | 尚未完成 / 验证边界 |
|---|---|---|
| Workspace | pnpm monorepo，TypeScript，锁定依赖版本 | 桌面安装包和跨平台分发未验证 |
| Runtime | 创建 Task/Session/Run，状态转换，推进、暂停、恢复、取消；Runtime 维护带 nonce/动作哈希/策略版本/有效期的 typed approval；版本化 Tool Registry、`workspace.inspect`、Coding read/edit/patch/test/diff、可选 Docker Coding Sandbox、Office DOCX/XLSX/PDF Profiles/Policy/Worker Client/Verifier、bounded/redacted Context（Pinned/Recent/Cold、compaction gaps）/Tool schema/ToolResult、UsageLedger、Episode/release gate、带 source Episode/trace、风险、证据引用和 review version 的 Experience Candidate review、owner/lease、ArtifactStore、Provider request IDs 和 Run cancellation signal；预算与对账从持久事件重建，`run.reconciled` 只接受证据包；AgentRunCoordinator 持久化 child identity、parent/root lineage、角色、能力、scope、目标、预算和状态，并限制 fan-out/并发、记录 child usage、支持级联取消与恢复；ConnectorRegistry 支持版本化 target/action profile、allowlist、字段/scope 检查、dry-run preview、Loopback 幂等写入和只记录 hash/version 的脱敏 receipt；read-after-write verifier、受限证据 Artifact 与 UNKNOWN/reconciliation；BrowserFixtureRegistry 的 context/origin/window/app scope、导航、DOM assertion、screenshot Artifact 和生命周期事件；版本化 Browser Action Profile、受控 Artifact I/O 与高风险审批；Browser Action 后置条件 verifier、页面/窗口/网络故障注入、UNKNOWN/reconciliation 和幂等回放；A2A loopback envelope、身份/HMAC fixture、能力/scope/deadline/Artifact 校验、queued/sent/ack/failed/unknown、attempt、late-ACK 和 `a2a.reconciliation` 持久状态与重启重放；RemoteAgentCoordinator 通过 child correlation 执行最小上下文、typed Result/Evidence/Artifact 并把远程 proposal 重新送入本地 ActionGateway；远程动作再经过 endpoint allowlist、禁止本地 capability、ArtifactStore hash/bytes 和 postcondition gate | Docker daemon/image 未配置时 Coding 仍按 fail-closed；真实目标环境的供应商/Office 依赖仍待集成验证；Loopback 之外的真实外部系统和真实连接器 smoke 仍待补 |
| Event Ledger | 内存账本和原生 Node `node:sqlite` 账本；schema v1 migration、WAL/事务、append-only sequence、durable task/session/run/checkpoint/receipt/verification projections；ActionGateway 的 requested/approval/approved/denied/receipt 事件纳入版本化事件类型 | 原生 SQLite 使用 Node 22 experimental API；跨客户端 ownership 和分布式锁不在 T2 |
| 元数据恢复 | 第二 Runtime 可重开并 replay Task/Session/Run；checkpoint、pending approval、known receipt、unknown-side-effect reconciliation、SQLite 原子 owner lease、shutdown 安全暂停和 JSONL 脱敏导出可恢复；CLI/Desktop 使用独立 owner 标识并可重连控制 | 完整打包应用重启后的长任务现场回归仍需单独执行 |
| Policy / Executor | 默认 deny；显式 allow 后执行；未配置执行器会失败；ask 记录原始 ToolCall、workspace scope 并等待 typed approval；approve 续行原 Run，deny 不调用 executor；`workspace.inspect` 与 Coding read/edit/patch/test/diff 使用版本化 Profile、路径守卫和 bounded 输出；patch 的 base hash、上下文和唯一匹配检查失败时生成 `coding-conflict` Artifact 且不写入文件；写入与测试通过可选 Docker Sandbox，后端缺失时 fail-closed；ActionGateway 统一 schema/scope/policy/approval/adapter/receipt 顺序 | 目标环境 Docker image/daemon smoke、跨客户端 ownership 和完整打包回归待补 |
| 执行回执 | 失败且 receipt.sideEffect 为 unknown 时进入 needs_reconciliation；tool receipt/observation 写入事件账本；inspect receipt 含 profile、`sideEffect:none`、稳定 `workspace://` Artifact 引用和 hash；CLI/Desktop 可查询候选并提交证据对账 | 完整异常路径和真实外部系统对账待补 |
| Budget | 循环入口检查步骤和本次 run() 调用耗时；Provider request 带剩余 timeout，cancel 会 abort 在途 Provider；UsageLedger 去重 requestId 并对 Token/费用超限硬暂停；`getBudgetUsage` 从 ledger 累计 steps/time/token/cost/latency/retry/cache/reviewer | 目标环境长任务现场回归待补 |
| Verifier | 非空文本 passed，空文本 unknown 并暂停；`WorkspaceInspectVerifier` 要求成功 inspect receipt、版本 Profile、稳定 URI 和 hash；`CodingVerifier` 要求 read、edit/patch、passing test、diff 与 Coding Artifact 回执后才 passed；`OfficeVerifier` 按 DOCX/XLSX/PDF evidence checks 放行，缺渲染/OCR/覆盖率/范围证据返回 UNKNOWN；release gate 拒绝失败、未知 action/child 副作用、泄漏或未对账 Episode | 真实 coding sandbox 之外，LLM Judge 仍只作为未来的 advisory 层 |
| Provider | OpenAI-compatible adapter 支持 structured messages/Context/Tool schema/ToolResult、request/attempt/trace、usage/cost、AbortSignal/timeout、retryable failure taxonomy；DeepSeek/Zhipu/Kimi fixture 共享合同；DeepSeek/智谱默认走 Runtime SSE stream seam；Keychain resolver 缺失时 fail-closed，不发 HTTP 请求；`providerTrace.requestSummary` 只记录有界计数/长度和 transport | DeepSeek/智谱真实凭据、真实文本/工具调用、真实 SSE、限流与认证 smoke 仍待目标环境；fixture 不代表真实联调 |
| CLI | Runtime → JSON 汇总；`inspect [path]`、`HELM_TASK_KIND=coding` 和 `HELM_TASK_KIND=office` 走对应 Runtime Tool Registry/Policy/Executor/Verifier 语义；`HELM_STATE_DB` 接入 SQLite；`HELM_PROVIDER=deepseek|zhipu|kimi` 读取对应 Keychain 配置；`HELM_CODING_SANDBOX=docker` 启用受限 Coding backend；`control`、`approve`、`reconcile`、`agent list/create/cancel/recover`、`connector list/register/preview/write/verify`、`browser list/create/navigate/approve/assert/control/profile-list/profile-register/action/action-approve/verify`、`a2a list/retry/reconcile`、`export`、`--jsonl` 共用 Runtime 的 Run/Artifact/Approval/Verification projection、Episode 和脱敏 JSONL | Docker image/daemon 和 DeepSeek/智谱真实凭据需在目标环境验证 |
| Desktop | 三栏对话优先 UI；Renderer 通过 typed preload/IPC 提交、控制、审批、对账、child AgentRun 和 Connector preview；Main 默认打开 userData SQLite，按事件与快照投影消息、Approval、Verification、Trace 和 Episode；`HELM_TASK_KIND=coding|office` 接入对应 Runtime（Coding 缺 Sandbox 时 fail-closed，Office 使用真实 JSONL worker）；右栏按同一 projection 展示 Coding diff、测试命令/结果、冲突 Artifact 和 Verification evidence；`DesktopWindowRegistry` 按窗口/Run 授权广播去重事件，重连 snapshot 触发 Runtime recovery；快照与 `run-export` 共用 Runtime 的 Run/Artifact/Approval/Verification projection | packaged restart smoke 使用 MockProvider 快速 Run；真实长任务、跨平台安装包和多机窗口仍待目标环境回归 |
| IPC | runtime-info、run-start、run-snapshot、run-control、run-approval、run-reconciliation、agent-list/create/control、connector-list/register/preview/write/verify、browser-context-list/create/navigate/approve/assert/control、browser-profile-list/register/action/action-approve/verify、a2a-list/control、run-export、run-event；Main 做来源/请求/workspace 校验，窗口按 Run 授权并转发带 runId/sequence 的脱敏事件；snapshot 重连触发 recovery | 跨平台安装包、真实长任务退出恢复和多机分布式窗口不在当前 smoke |
| Python worker | stdio JSONL health/inspect；health 预检返回 worker/工具/Python 依赖版本、路径和 missing；bounded DOCX 生成并检查 package/content，若有 `soffice`/`libreoffice` 则在临时目录执行有界 PDF 转换和页数检查；XLSX 单元格/范围读写并做 bounded workbook fingerprint（值/公式类型/样式/合并/defined names）与 target/scope snapshot；PDF text-layer 分页来源与 textHash/coverage，若有 `pdftoppm`/`tesseract` 则执行带页码、engine 和 confidence 的逐页 OCR；Artifact evidence 汇总 checks、target、OCR、preflight、limitations 和 workspace path guard | 外部依赖缺失时仍按 UNKNOWN 阻断交付；未做像素级视觉比较 |

Keychain、受限 shell、真实工件存储和 Office Runtime verifier 已接入；Electron renderer sandbox 仍不等于工具执行 sandbox。Office 的 OCR/渲染依赖缺失时必须保留 UNKNOWN，不得把文本非空当作通过。

| `pnpm test` | 通过 | Runtime 91 项、Provider 9 项、Desktop IPC 11 项；SQLite、Provider、Coding、Office/OCR、Browser、A2A 投递对账和 Remote Agent 本地安全门禁合同使用 fixture，Kimi 真实请求单独记录 |
